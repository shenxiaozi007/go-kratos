# 后端开发文档：萌宠之家

本文档约定萌宠之家在 realworld（Kratos）后端的服务边界、API 设计、鉴权与错误约定、以及 Proto/Biz/Data/Service 实现要点。

---

## 1. 服务边界

- 在 realworld 仓库内扩展，不新建独立服务。
- 新增 **api/pet/v1**（及可选 api/checkin、api/shop 等）Proto 与对应 Service；与现有 api/auth、api/game 等并存。
- 所有宠物相关接口除登录/注册外均需 **JWT 鉴权**，通过 `auth.FromContext(ctx)` 取当前用户 ID。

---

## 2. 通用约定

- **Base URL**：与 realworld HTTP 一致，如 `http://localhost:8000`。
- **鉴权**：请求头 `Authorization: Bearer <JWT>`；未携带或无效返回 `401 Unauthorized`。
- **Content-Type**：请求/响应 `application/json`，UTF-8。
- **错误响应**：JSON，如 `{ "code": 400, "reason": "BAD_REQUEST", "message": "具体原因" }`；HTTP 状态码与 code 一致或按 Kratos 约定。

## 3. API 清单（按模块）

### 3.1 认证（沿用现有）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/v1/auth/register | 注册，Body: username, password；返回 user_id, username |
| POST | /api/v1/auth/login | 登录，Body: username, password；返回 token |
| GET | /api/v1/auth/profile | 当前用户（含 nickname, avatar_url, signature, level, coins, heart_points） |

### 3.2 用户扩展

| 方法 | 路径 | 说明 |

| GET | /api/v1/user/profile | 同 auth/profile 或合并 |

### 3.3 宠物

| 方法 | 路径 | 说明 |

## 4. 宠物接口请求/响应示例

### GET /api/v1/pet/me 响应（200）

```json
{
  "id": 1,
  "user_id": 100,
  "name": "小橘",
  "species": "CAT",
  "mood": "非常开心",
  "affection": 750,
  "fullness": 85,
  "happiness": 92,
  "cleanliness": 70,
  "avatar_url": "https://...",
  "background_url": "https://..."
}
```

- `affection`：亲密度 0–1000（与原型 750/1000 一致）。
- `fullness` / `happiness` / `cleanliness`：饱食度/心情值/清洁度 0–100。

### POST /api/v1/pet/interact 请求

```json
{ "action": "STROKE" }
```

- `action`：STROKE | TEASE | TREAT | BATH。
- 响应为更新后的宠物对象（同 GET /api/v1/pet/me 结构）。

## 5. 实现要点（realworld）

### 5.1 Proto

- **位置**：api/pet/v1/pet.proto。
- **内容**：Pet 消息（含 id, user_id, name, species, mood, affection, fullness, happiness, cleanliness, avatar_url, background_url）；GetMyPet、CreateOrUpdatePet、Interact 等 RPC，并配置 google.api.http 路径为 /api/v1/pet/...。
- 生成：`make api` 或 kratos proto client/server，生成 Go 与 HTTP 绑定。

### 5.2 Biz 层

- **位置**：internal/biz/pet.go。
- **领域模型**：Pet（含成长数据字段）。
- **Repo 接口**：PetRepo：GetByUserID、Save、UpdateAffectionAndMood 等。
- **用例**：PetUsecase：GetMyPet、CreateOrUpdatePet、Interact（按 action 计算亲密度与成长数据变化）。
- 在 internal/biz/biz.go 的 ProviderSet 中注册 NewPetUsecase。

### 5.3 Data 层

- **位置**：internal/data/pet.go。
- **PO**：PetPO，表名 pets；字段与 [database/](database/) 一致。
- 实现 PetRepo；在 internal/data/data.go 的 ProviderSet 与 AutoMigrate 中加入 PetPO、NewPetRepo。

### 5.4 Service 层

- **位置**：internal/service/pet.go。
- PetService 实现 proto 生成的 PetServiceHTTPServer；每个方法内 `auth.FromContext(ctx)` 取 UserID，未取到返回 401。
- 在 internal/service/service.go 注册 NewPetService；在 internal/server/http.go 注册 pet 路由（petv1.RegisterPetServiceHTTPServer），并在 NewHTTPServer 中注入 PetService。

### 5.5 Wire

- 在 data、biz、service 的 ProviderSet 中加入 pet 相关 New 后，运行 `wire` 生成 cmd/realworld/wire_gen.go；确保 HTTP 服务器注入 PetService。

## 6. 实现顺序建议

认证 → 宠物（含成长数据与互动）→ 签到 → 用户资料与金币/爱心积分 → 商店与背包 → 领养/品种 → 换装 → 社交 → 成就。

**当前已实现**：宠物、签到、用户资料；商店与背包；领养与品种；换装；成就；社交（好友、申请、排行榜）。**成就解锁**：签到/领养/购买时自动尝试解锁成就（first_checkin、first_pet、first_purchase），AchievementRepo.GetByCode/Unlock、AchievementUnlocker 注入到 Checkin/Pet/Shop 用例。**种子数据**：启动时若 achievements/shop_items/breeds 表为空则写入默认数据（3 条成就、6 条商品、6 条品种），见 data/seed_catadmin.go。

数据库表结构见 [database/](database/)。
