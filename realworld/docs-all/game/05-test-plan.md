# 测试规划：防守割草小游戏

本文档约定测试策略、用例类型、环境与性能要求。

---

## 测试策略

| 类型 | 范围 | 说明 |
|------|------|------|
| 后端单元测试 | biz 层 | 分数校验、排行榜逻辑、最高分更新与边界条件 |
| 后端接口测试 | HTTP API | 提交分数、排行榜分页、我的最高分、错误码与参数校验 |
| 后端并发/压力 | 提交分数、排行榜 | 多请求同时提交、排行榜高 QPS 读 |
| 前端单元测试 | 游戏逻辑 | 碰撞检测、技能效果、能量与等级计算（纯 JS/TS） |
| 前端组件/页面 | Vue 组件 | 主菜单、结算页、排行榜列表、升级弹窗（Vue Test Utils 等） |
| E2E / 手工 | 关键流程 | 主菜单 → 战斗 → 结算 → 再玩一次/返回；排行榜展示与分数一致性 |

---

## 后端测试

### 单元测试（biz 层）

- 分数提交：合法 score/wave 通过；超出合理范围（如 score &lt; 0 或 &gt; 上限）返回校验错误。
- 最高分更新：仅当本局分数大于当前最高分时更新；更新后排行榜数据一致。
- 排行榜：分页 page/page_size 边界；空列表与总数 total 正确。

### 接口测试

- **SubmitScore**：正常提交返回 success；缺少 user_id/openid 或非法参数返回 40002；同一局幂等（若支持 session_id）不重复计分。
- **GetLeaderboard**：page=1、page_size=20 返回 items 与 total；page 过大返回空列表；响应格式与 [errors-and-conventions](../xsh-docs/backend/errors-and-conventions.md) 一致。
- **GetMyBest**：有数据返回 best_score、best_wave；无数据返回 0 或 40001（按设计）。

### 并发与性能

- 多协程/多请求同时调用 SubmitScore，验证最高分与排行榜最终一致、无脏写。
- 排行榜接口 QPS 压测（如 100–500 QPS），Redis 与 DB 压力在可接受范围；响应时间 P99 达标（如 &lt; 200ms）。

## 前端测试

### 游戏逻辑单测（纯 JS/TS）

- 碰撞检测：子弹与怪兽矩形/圆相交判定；边界情况（刚好相切、不相交）。
- 技能效果：应用技能后子弹数量、角度或伤害系数符合配置。
- 能量与等级：击败 N 只怪兽后能量累加正确；达到阈值触发升级一次。

### 组件/页面

- 主菜单：展示最高分、点击开始游戏/排行榜跳转或弹窗。
- 结算页：展示本局得分与波数、再玩一次/返回主页按钮；提交分数成功/失败时的提示。
- 升级面板：展示 3 张卡、点击后关闭并继续游戏。

### E2E 或关键流程

- 主菜单 → 开始游戏 → 战斗（可简化为一键过关或短时间）→ 结算页 → 再玩一次回到战斗、返回主页回到主菜单。
- 主菜单打开排行榜，数据与后端一致（或 mock 数据一致）。
- 小程序真机或开发者工具内跑通上述流程，无白屏与未捕获异常。

---

## 环境与数据

- **测试环境**：与开发/生产隔离的 API baseURL；测试库 MySQL、独立 Redis（或 mock）。
- **Mock 数据**：种子用户与分数，用于排行榜与「我的最高分」联调；提交分数可先写测试用户。
- **微信**：真机测试时使用测试号或体验版；登录接口可用 mock 或测试 openid。

---

## 性能与监控（建议）

- 排行榜接口：P95/P99 延迟、错误率；Redis 命中率。
- 提交分数：成功率、重复提交拦截率（若实现防重）。
- 前端：Canvas 帧率（目标 ≥ 30 fps）、首屏与页面切换时长；关键操作埋点便于分析（可选）。
