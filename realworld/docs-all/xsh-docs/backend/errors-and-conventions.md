# 错误响应与通用约定

本文档约定 xsh 相关 API 的错误格式、分页与时间字段，便于前后端统一实现。详见 [api-catalog.md](api-catalog.md)。

---

## 错误响应

- **HTTP 状态码**：业务错误仍返回 200，通过 body 内 `code` 区分；或采用 Kratos 推荐方式，非 2xx 时 body 为错误详情。
- **统一错误体**（推荐）：`{ "code": 40001, "message": "商品不存在" }`。前端可根据 `code` 做统一提示；后端使用 Kratos errors 或自定义 code 与 message。
- **业务错误码示例**（可扩展）：
  - `40001`：资源不存在（如商品/草稿/账号/任务）
  - `40002`：参数校验失败
  - `40003`：草稿状态不允许操作（如已发布不可再创建任务）
  - `50001`：外部服务失败（如 Gemini、OSS 上传）

---

## 分页约定

- **page**：从 **1** 开始。
- **page_size**：默认 **20**，最大 **100**；超出时按 100 处理或返回 40002。
- 所有 List 类接口请求与响应均遵循上述约定，响应包含 `items`（或与 proto 一致）与 **total**（总条数）。

---

## 时间字段类型

- Proto 中时间字段统一使用 **google.protobuf.Timestamp**，与现有 realworld 一致；生成 JSON 时为 RFC3339 字符串。
- 若与现有项目统一用 int64（Unix 秒），则在所有 xsh proto 中保持一致，并在生成代码与前端解析时统一处理。
